# AI Living Town 长期开发规划树

> 适用项目：AI Companion Demo / Living Agent Runtime  
> 规划基线：2026-07-23  
> 目标：从“两个 AI 角色生活在客厅中的 Demo”演进为可扩展、可开源、可导入角色与场景的 AI 生活小镇平台。

## 1. 规划使用方法

这不是一条只能顺序执行的路线，而是一棵可以并行生长的规划树。

- 每个节点有稳定编号，例如 `S3.1`、`C4.2`。Issue、提交说明和版本计划应引用该编号。
- 每个版本是从不同分支选择节点组成的“版本切片”，不要求完整做完一个大分支才进入另一个分支。
- 每个版本最多选择一个基础设施主任务和两到三个用户可见主任务，避免同时扩张过多系统。
- 角色、场景和玩家使用相同的空间、交互、资产导入与存档协议，防止形成三套互不兼容的实现。
- 碰撞、导航、物体所有权等确定性逻辑必须由本地 Runtime 执行；LLM 只能给出受约束的目标和计划。

状态标签：

- `[DONE]`：已有可运行实现和基础验收。
- `[ACTIVE]`：已有基础实现，但仍在当前阶段持续迭代。
- `[NEXT]`：建议进入最近一到两个版本。
- `[LATER]`：依赖其他分支，适合后续版本。
- `[RESEARCH]`：需要实验验证，不能直接承诺产品化。

## 3. T 分支：Runtime 主干

### T1. 认知与动作协议 `[ACTIVE]`

当前基础：

- `MessageBus → CognitiveCycle → GOAPPlanner → ActionExecutor → AgentBase` 已可运行。
- LLM 可以返回 `goal`、`gesture`、`motion_query`、`expression_query` 和受限 `plan`。
- 本地规则与本地路由模型可在 LLM 不可用时降级运行。

后续节点：

- `T1.1 [NEXT]` 将动作结果统一为结构化 `PerformanceIntent`：动作、表情、视线、速度、强度、目标物体、持续时间。
- `T1.2 [NEXT]` 为动作增加中断、优先级、互斥组和恢复策略，防止说话、走路、挥手相互抢占。
- `T1.3 [LATER]` 支持层级计划：长期目标、日程、短期行为和即时反应。
- `T1.4 [LATER]` 增加可解释决策日志，让开发者看到“为什么选择这个动作”。
- `T1.5 [DONE prototype]` 建立 LangGraph 兼容 AgentState 与共享认知图；按
  `thread_id=agent:<agent_id>` 隔离角色 checkpoint，Godot 保持物理执行权。

### T2. 语义世界与空间协议 `[ACTIVE]`

- `T2.1 [NEXT]` 统一 `SceneObjectDescriptor`：语义 ID、类型、状态、交互点、抓取点、观察点、碰撞范围和权限。
- `T2.2 [NEXT]` 将物体位置从硬编码坐标升级为场景注册和运行时空间查询。
- `T2.3 [LATER]` 支持跨房间位置图、门、楼层、街区和交通节点。
- `T2.4 [LATER]` 支持对象所有权、容器关系和位置关系，例如“书在书架第二层”。

### T3. 插件接口 `[NEXT]`

- 定义 `CharacterAdapter`、`SceneAdapter`、`MotionProvider`、`ExpressionProvider`、`VoiceProvider`。
- 核心 Runtime 不直接依赖企鹅、诀、客厅或 ECNU 服务。
- 所有扩展通过资源文件、注册表和稳定信号接入。

### T4. 工程底座 `[NEXT]`

- 建立存档 Schema、资源版本、迁移脚本和兼容策略。
- 给每个关键协议增加 headless 合同测试。
- 建立 30/60 FPS、内存、模型面数、贴图和 AI 延迟预算。

## 4. S 分支：场景与世界

### S1. 场景美术、UI 与视听表现 `[ACTIVE]`

当前已有暖色客厅、PBR 家具、环绕相机、温馨 UI、输入焦点和基础环境背景。

- `S1.1 [NEXT]` 聊天消息气泡化、折叠聊天记录、角色头像、目标角色选择器。
- `S1.2 [NEXT]` 完善家具比例、接触阴影、墙体细节、窗景、昼夜灯光和环境音。
- `S1.3 [NEXT]` 响应式 UI：窗口缩放、16:9/16:10、超宽屏和高 DPI。
- `S1.4 [LATER]` 设置页、模型/音频/AI 状态页和开发者诊断面板。
- `S1.5 [LATER]` 摄影模式、景深、镜头预设和截图/录像。

验收标准：主要物体不悬空、不穿模；1280×720 至 2560×1440 可读；UI 不抢占相机输入；场景在目标设备达到性能预算。

### S2. 多房间、街道与小镇 `[NEXT]`

- `S2.1` 将客厅拆成可加载的 `WorldLocation`，加入入口、出口和出生点。
- `S2.2` 增加厨房、卧室、走廊，形成第一套住宅。
- `S2.3` 接入庭院和“晓光忆时”作为独立地点，不直接替换客厅。
- `S2.4` 增加街道、咖啡馆、公园等公共地点。
- `S2.5` 实现场景流送、远景代理、跨场景导航和角色离屏模拟。

建议先完成住宅内部，再建设街道；否则跨场景导航、存档和角色日程会反复返工。

### S3. 可交互物体与状态变化 `[ACTIVE]`

第一批状态机：

- `S3.1 [DONE baseline] 盆栽`：含水量、健康、成长阶段、枯萎、浇水、恢复、语义同步和存档。
- `S3.2 奶茶/食物`：容量、新鲜度、持有者、饮用次数和空杯状态。
- `S3.3 书`：所在位置、阅读进度、当前读者和放回位置。
- `S3.4 电视`：开关、频道、音量、观看者和节目事件。
- `S3.5 门/灯/柜子`：开关、阻挡状态、容器内容和使用权限。

每个物体需要同时具备：

1. 可持久化状态；
2. 场景视觉反馈；
3. SemanticWorld 描述；
4. 可执行 Affordance；
5. 碰撞与交互锚点；
6. 自动化状态转换测试。

### S4. 参数化建模与自动场景生成 `[RESEARCH]`

- `S4.1` 参数化单房间：尺寸、门窗、墙体、地板、家具槽位。
- `S4.2` 约束式家具布置：通道宽度、可达性、视线、碰撞和风格约束。
- `S4.3` 模块化住宅生成：房间连接图、楼层和功能分区。
- `S4.4` 街区生成：道路图、地块、建筑模块和公共空间。
- `S4.5` 自然语言生成场景配置，但必须经过确定性约束求解与导航验收。

技术原则：生成结果应保存为可编辑的参数和场景资源，而不是一次性不可复现的网格。

### S5. 世界模拟 `[LATER]`

- 日夜、天气、季节、室内外光照与环境音。
- 植物、食物、清洁度、能源等缓慢状态变化。
- 居民日程、地点开放时间、公共事件和节日。
- 离屏角色使用低频符号模拟，进入视野后恢复完整物理和动画。

## 5. C 分支：AI 角色

### C1. 文本到动作/表情路由 `[ACTIVE]`

当前真实链路：

```text
玩家输入
  -> LLM 输出 gesture / motion_query / expression_query
  -> 高置信场景规则
  -> 本地 hash n-gram 质心路由
  -> action_id / expression payload
  -> 角色适配器
```

并非所有动作都来自 LLM：导航状态机、GOAP、ActionExecutor 和自主需求也可以直接触发动作。

- `C1.1 [NEXT]` 记录 query、候选、分数、最终动作和人工评价，建立真实交互数据集。
- `C1.2 [NEXT]` 把 ECNU embedding 接入可选本地后端；动作库 embedding 离线缓存，运行时只计算查询向量。
- `C1.3 [NEXT]` 训练轻量双头/多头路由器：动作类别、表情混合、强度、目标和是否需要移动。
- `C1.4 [LATER]` 本地 ONNX/小模型推理，网络不可用时仍能低延迟匹配。
- `C1.5 [LATER]` 融合上下文：角色当前姿势、手中物体、距离、情绪和动作冷却。

目标指标：路由 P95 延迟低于 100 ms（本地）或 350 ms（远端 embedding）；常用动作 Top-1 准确率达到可维护测试集的 90% 以上。

### C2. 动作库与骨骼重定向 `[ACTIVE]`

- 当前企鹅有已烘焙动作；诀使用轻量骨骼覆盖和程序化兜底。
- HumanML3D/Light-T2M 已建立离线包和 22 关节映射，但真实批量样本仍待服务器生成与验收。

后续：

- `C2.1 [NEXT]` 建立 20–30 个核心动作：自然待机、行走、转身、挥手、点头、坐下、拿取、放下、喝、读、指向等。
- `C2.2 [NEXT]` 完成诀的 Blender 重定向与烘焙动画，替代程序化上臂动作。
- `C2.3 [NEXT]` 建立统一动作元数据：循环、root motion、占用身体层、目标、接触事件和适用骨架。
- `C2.4 [LATER]` 足锁、手部接触、关节限幅、穿模检测和循环过渡。
- `C2.5 [RESEARCH]` Light-T2M 生成候选动作，离线筛选后进入正式动作库；不直接控制碰撞关键行为。

### C3. 表情和身体语言 `[ACTIVE]`

- `C3.1 [NEXT]` 为每个角色建立 BlendShape/骨骼表情适配表和覆盖率报告。
- `C3.2 [NEXT]` 眨眼、视线、注视目标、头部朝向和说话口型。
- `C3.3 [NEXT]` TTS 音素/振幅驱动的基础口型同步。
- `C3.4 [LATER]` 采用 VRM/ARKit 风格表情协议，支持更丰富模型。
- `C3.5 [LATER]` 表情、姿势和语音语气的统一情绪连续性。

### C4. 角色与场景交互 `[ACTIVE]`

- `C4.0 [DONE baseline]` 缺水盆栽触发 `走近 → 浇水 → 走到沙发 → 坐下休息`，玩家输入可抢占。
- `C4.1 [NEXT]` 所有角色具备准确碰撞体、导航半径和动态避障。
- `C4.2 [DONE baseline]` 行为计划引用语义物体 ID 与 interaction point，不让 LLM 保存绝对坐标。
- `C4.3 [ACTIVE]` 目标物体提供 approach/grab/look/sit 等交互锚点；盆栽和沙发已接入。
- `C4.4` 实现 `走近 → 对齐 → 伸手 IK → 抓取 → 持有 → 使用 → 放回`。
- `C4.5` 失败处理：物体被占用、路径阻塞、目标移动、动作取消和重新规划。
- `C4.6` 多角色接触：握手、递物、并排坐、共同观看和保持社交距离。

验收标准：角色不能隔空拿取、穿过家具或在目标不可达时假装成功。

### C5. 记忆、人格、日程与社交 `[ACTIVE]`

当前两个角色已经按 `agent_id` 隔离记忆，并有保守的社交回应。

- `C5.0 [DONE baseline]` 自主行为完成后分别记录行动者/观察者 Episode，并更新观察者对行动者的 respect。
- `C5.0a [DONE baseline]` OCEAN、动机、持续心境、注意、当前意图、私密想法和
  简化 Theory of Mind 已按角色隔离并进入存档；LLM 上下文能读取但不得当作客观事实。
- `C5.1 [NEXT]` Reflection、语义记忆压缩和长期事实更新。
- `C5.2 [NEXT]` 关系图：熟悉、信任、好感、冲突、共同经历。
- `C5.3 [NEXT]` 日程、地点偏好、习惯和需求驱动的长期目标。
- `C5.4 [LATER]` 多 Agent 对话轮次、打断、旁听、加入/离开和群体注意力。
- `C5.5 [LATER]` 社交事件、关系变化和跨天连续剧情。
- `C5.6 [LATER]` 离屏角色低成本模拟与重新进入场景时的状态恢复。

### C6. 角色导入与人设定制 `[LATER]`

- 支持 GLB/GLTF，后续可选 VRM；FBX/MMD 通过离线转换工具进入标准格式。
- 导入向导检查比例、朝向、骨骼、材质、BlendShapes、动画和许可证。
- 自动生成骨骼候选映射，用户可在 UI 中修正。
- 人设包包含身份、说话风格、边界、关系初始值、兴趣、日程和语音配置。
- 角色包必须与存档分离，使升级模型不会清空角色记忆。

### C7. 实时语音与听觉 `[ACTIVE]`

- 当前 ECNU TTS 已支持异步句子分块播放。
- `C7.1 [NEXT]` 每角色独立 voice、速度、音量、队列和打断策略。
- `C7.2 [NEXT]` TTS 缓存、失败降级、字幕与音频同步。
- `C7.3 [LATER]` 真正 PCM/Opus 流式播放和口型同步。
- `C7.4 [LATER]` 玩家语音输入、VAD、ASR 和说话者指向。
- `C7.5 [RESEARCH]` 用户授权的自定义音色；必须包含隐私、同意和滥用防护。

### C8. 角色美术 `[ACTIVE]`

- 统一真实身高、材质色彩空间、阴影、LOD 和移动端规格。
- 修复诀的衣服、袖片、头发和物理骨骼；建立近景/远景材质。
- 服装和配饰使用插槽协议，避免每套服装复制完整角色。
- 为角色建立缩略图、头像、表情预览和质量等级。

### C9. 角色生活感与行为连续性 `[NEXT]`

当前 `盆栽缺水 → 浇水 → 沙发休息` 已形成确定性闭环，但仍容易被感知为
“事件触发脚本”，还不是持续生活。生活感优化不得只增加随机台词，而应同时
补齐动机、身体接触、过渡行为、个性差异和共同活动。

目标架构：

```text
环境状态 + 身体需求 + 日程 + 关系 + 近期记忆
  -> 感知与可见/可达性过滤
  -> Utility AI 候选活动评分
  -> HTN / GOAP 受约束任务分解
  -> 导航、占用、对齐、IK 与物体交互
  -> 动作、视线、表情、语音与环境反馈
  -> 结果写回世界状态和每角色独立记忆
```

规划节点：

- `C9.1 [DONE baseline]` Utility AI 生活调度器：已按需求缺口、环境紧迫度、人格偏好、
  距离和冷却计算候选活动分数，并提供选择诊断；后续补日程和社交上下文。
- `C9.2 [ACTIVE]` 微行为层：已有按角色配置、带冷却且无对白刷屏的注视/思考基线；
  后续增加呼吸、眨眼、重心变化、环顾、转身、整理衣物、
  看附近物体、听见说话时转头，以及坐下后的姿势调整。
- `C9.3 [ACTIVE]` 行为过渡和承诺：已有目标朝向、活动资源锁、完成后安静期和玩家抢占；
  后续增加短暂停顿、起身、执行、
  检查结果、决定恢复原任务或重新规划；避免角色瞬间切换目标。
- `C9.4 [DONE baseline]` 咕咕嘎嘎与诀已有独立活动偏好、微行为配置、需求状态和
  结果记忆；后续补地点偏好、作息、动作速度、社交阈值和表达方式。
- `C9.5 [NEXT]` 完整浇水样板：寻找水壶、占用、走近、对齐、手部 IK 抓取、携带、
  倒水动画、水流粒子/音效、植物反馈和水壶归位。
- `C9.6 [NEXT]` 共同活动协议：邀请、接受/拒绝、等待、并行走位、座位预订、
  共同看电视/读书/照顾植物、短对话和自然结束。
- `C9.7 [LATER]` 生活节奏控制：避免频繁走动和台词刷屏，引入安静时段、活动时长、
  注意力、疲劳、恢复原任务和可被玩家打断的优先级。
- `C9.8 [LATER]` 生活感诊断面板：开发模式显示候选活动、评分原因、当前目标、
  行动步骤、占用资源和失败原因；正式模式隐藏系统日志。

实现原则：

- Utility AI 决定“现在更想做什么”，GOAP/HTN 决定“如何安全完成”。
- LLM 负责高层意图、自然语言、复杂社交判断和长期反思，不负责碰撞关键行为。
- 动作匹配模型只能改善动作选择，不能替代 interaction point、物体占用、IK 和碰撞。
- 随机微行为必须受姿势、附近物体、当前关注对象和冷却约束，不能成为无意义抖动。

五分钟生活感验收：

> 玩家不输入指令，连续观察五分钟，两个角色仍能表现出互不冲突、具有个性差异、
> 有开始/过渡/结束的连续生活；玩家中途插话时，目标角色会停下或安全收尾、转向
> 玩家并回应，随后根据上下文恢复原任务或重新选择目标。

量化检查：

- 五分钟内至少出现 3 类不同活动，且同一活动不会无意义连续重复。
- 至少一次由环境/需求触发的物体交互和一次角色间共同活动。
- 角色不会隔空交互、抢占同一座位/物体、穿过主要家具或在路径失败后假装成功。
- 玩家消息到角色产生可见注意力反馈的延迟低于 500 ms；完整语言回复可异步到达。
- 每个重要行为能够在诊断面板解释选择原因和执行结果。

## 6. P 分支：玩家

### P1. 玩家形象 `[LATER]`

- 预设玩家模型和基础换装。
- 使用与 AI 角色相同的导入验证器接入用户 GLB/VRM。
- 第一人称可隐藏头部/身体局部，第三人称显示完整动画。

### P2. 控制与镜头 `[NEXT]`

- `P2.1` 保留当前房间中心观察相机作为“导演/布置模式”。
- `P2.2` 增加第三人称移动、碰撞、上下楼和交互射线。
- `P2.3` 增加第一人称视角、灵敏度和晕动减缓选项。
- `P2.4` 在观察、第一和第三人称模式间安全切换。

### P3. 玩家交互 `[NEXT]`

- 对话目标选择、靠近交谈、指向和注视反馈。
- 拿取、放置、赠送、共同使用物体。
- 邀请角色跟随、去某处、坐下、一起活动。
- 角色应基于关系、人设和当前计划接受、协商或拒绝，而不是无条件服从。

### P4. 个性化与可访问性 `[LATER]`

- 键鼠/手柄重映射、字幕、字号、色弱、减少镜头运动。
- 玩家偏好、关系历史、房屋布置和收藏。
- 可选儿童/家庭安全配置与内容过滤。

## 7. D 分支：剧情与导演

### D1. 小剧本输入 `[NEXT]`

建议定义可验证的 YAML/JSON 剧本格式：

```yaml
title: 一起看电视
cast: [main_agent, jue_agent]
beats:
  - speaker: main_agent
    say: 我们一起看电视吧。
    gesture: wave
  - actor: jue_agent
    move_to: tv
  - actor: jue_agent
    gesture: nod
    say: 好。
```

- 解析后只生成白名单内的对白、动作、地点和物体交互。
- 缺失动作自动使用安全回退；不可达位置必须报告而不是跳过。
- 剧本角色可以绑定现有 Agent，也可以定义临时角色槽位。

### D2. 导演系统 `[LATER]`

- 时间线、Beat、同步点、等待条件和超时。
- 多角色走位、朝向、动作、表情、语音和镜头调度。
- 场景状态锁，避免自主行为在剧情关键帧打断演出。
- 剧情结束后恢复 Agent 原日程和记忆。

### D3. AI 辅助剧情 `[LATER]`

- LLM 把自然语言剧本转为受约束的结构化剧本。
- 只允许在导演定义的“即兴槽位”中扩写对白。
- 角色人设、关系和已有记忆影响即兴内容。
- 生成结果必须可预览、编辑和重放。

### D4. 创作与输出 `[LATER]`

- 时间线编辑器、镜头轨道、对白编辑和动作替换。
- 保存为项目内剧情资产，支持版本管理。
- 回放、字幕导出、截图和视频录制。

## 8. O 分支：开源与创作者生态

### O1. Runtime 插件化 `[NEXT]`

- 将 `Living Agent Runtime` 与 Demo 资产彻底分层。
- 定义语义版本、弃用周期和插件兼容矩阵。
- 提供最小 Godot 示例：单 Agent、双 Agent、交互物体、剧情导演。

### O2. 导入工具 `[LATER]`

- 角色导入向导、骨骼映射、动画覆盖率和表情预览。
- 场景扫描器自动发现门、地面、障碍和可交互物体。
- 资产检查报告可在命令行和 Godot 编辑器中运行。

### O3. Mod 与数据包 `[LATER]`

- 角色包、场景包、动作包、表情包、剧情包使用独立 Manifest。
- Mod 默认只能访问受限数据和信号，不能执行任意系统命令。
- 提供官方模板、示例资产和升级指南。

### O4. 开源治理与安全 `[NEXT]`

- 明确代码许可证和每项资产许可证；不可再分发资产不得进入仓库。
- API Key、语音样本、聊天记录和用户模型默认不提交、不上传。
- 为外部模型、脚本和 Mod 设置大小、格式、路径和内容校验。
- 建立贡献指南、行为准则、Issue 模板和安全漏洞报告流程。

### O5. 社区分享 `[RESEARCH]`

- 优先支持可导出的本地包；在线市场或公共索引放到稳定 API 之后。
- 分享角色时默认不包含私密记忆、玩家聊天和受限音色。

## 9. X 分支：横向工程能力

### X1. 存档和迁移 `[ACTIVE]`

- `[DONE baseline]` Schema v1 已保存世界时间、需求、物体状态和已加载角色位置。
- 后续加入关系、记忆引用、日程、剧情进度和跨场景位置。
- 原子写入、备份、损坏恢复和 Schema 迁移。
- 角色模型资源与角色身份/记忆分离。

### X2. 测试和性能 `[ACTIVE]`

- 保留现有 headless 合同测试并增加视觉基准截图。
- 新模型导入必须通过朝向、比例、T Pose、骨骼、动画和材质检查。
- 建立多 Agent 压力测试：2、10、30 个离屏/在屏 Agent。
- 记录 AI、路由、TTS、导航、动画和场景加载延迟。

### X3. AI Provider 与成本 `[ACTIVE]`

- Chat、Embedding、TTS、ASR、Motion Provider 使用独立接口。
- 支持远端 ECNU、其他 OpenAI 兼容接口和本地模型。
- 超时、重试、熔断、缓存、配额和本地降级必须统一。
- 任何远端 AI 都不能阻塞 Godot 主线程。

### X4. 本地化与无障碍 `[LATER]`

- 中文/英文文本资源化，角色人设与剧情支持多语言。
- 字幕、音量分轨、UI 缩放、色弱和减少动态效果。

### X5. 发布与诊断 `[LATER]`

- macOS/Windows/Linux 导出模板与自动构建。
- 崩溃日志、匿名可选遥测和本地诊断包。
- 开发、测试、发行配置隔离，发行包不包含调试密钥和源资产。

## 10. R 分支：可扩展的未来任务线

## 14. 统一完成标准

任何规划节点标记为完成前，至少满足：

1. 有用户可见或 Runtime 可验证的结果；
2. 有失败与降级路径；
3. 不在代码或仓库中写入私密 API Key；
4. 有 headless 合同测试，视觉任务另有截图验收；
5. 更新相关协议、资产来源和开发文档；
6. 关键版本形成独立 Git 提交；
7. 新角色、新场景和新物体不依赖修改核心认知代码才能接入。
