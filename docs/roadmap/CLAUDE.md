# 开发规划文档维护规范

> 本文档定义了 `docs/roadmap/` 目录树下所有文档的编写、更新和引用规范。

---

## 1. 文档树结构约定

### 1.1 目录组织

```
docs/roadmap/
├── README.md                         # 根文档：项目总体介绍与总规划树
├── CLAUDE.md                         # 本文件：文档维护规范
├── 01-usage-guide.md                 # 规划使用方法
├── 99-dependencies.md                # 分支依赖关系
├── 100-version-slices.md             # 建议版本切片
├── 101-recent-priorities.md          # 近期版本优先级
├── 102-completion-standards.md       # 统一完成标准
│
├── T-runtime/                        # T 分支：Runtime 主干
│   ├── README.md                     # 分支总览 + 子文档索引
│   ├── T1-cognition-action-protocol.md
│   ├── T2-semantic-world.md
│   ├── T3-plugin-interface.md
│   └── T4-engineering-foundation.md
│
├── S-world/                          # S 分支：场景与世界
├── C-characters/                     # C 分支：AI 角色
├── P-player/                         # P 分支：玩家
├── D-directing/                      # D 分支：剧情与导演
├── O-opensource/                     # O 分支：开源与创作者生态
├── X-engineering/                    # X 分支：横向工程能力
└── R-research/                       # R 分支：远期研究
```

### 1.2 分支目录命名

```
{分支代码}-{英文主题简写}-{中文主题}/
```

示例：
- `T-runtime/` —— Runtime 主干
- `C-characters/` —— AI 角色
- `X-engineering/` —— 横向工程能力

**规则**：
- 使用 ASCII 字母、数字和连字符
- 主题简写优先使用原文档中的英文关键词
- 中文主题可在 `README.md` 中标注，不放入目录名

### 1.3 子文档文件命名

```
{分支代码}{节点编号}-{英文关键词}.md
```

示例：
- `T1-cognition-action-protocol.md` —— T1 认知与动作协议
- `C5-memory-personality-schedule.md` —— C5 记忆、人格、日程与社交
- `S3-interactable-objects.md` —— S3 可交互物体与状态变化

**规则**：
- 分支代码 + 节点编号连接（如 `T1`、`C5`、`S3`），不带分隔符
- 英文关键词使用小写字母和连字符连接，控制在 3-6 个单词
- 根级文档以两位数字前缀排序：`01-usage-guide.md`、`99-dependencies.md`
- 不使用中文或特殊字符作为文件名

### 1.4 每个分支目录必须有 `README.md`

```markdown
# {分支名称} — 总览

> 所属系列：AI Living Town 开发规划树
> 分支代码：{T/S/C/P/D/O/X/R}

## 子文档索引

| 节点 | 文档 | 状态 | 简介 |
|------|------|------|------|

## 分支概述

（该分支的总体目标和核心原则）
```

## 2. 文档长度限制

### 2.1 最大长度

- **每篇文档不超过 500 行**（含空行和引用链接）
- 超过 500 行时，应检查是否可以拆分为更小的子文档
- 如果单个节点内容已接近 500 行，拆分为 `{Node}-part1.md`、`{Node}-part2.md`

### 2.2 子节点拆分标准

- 当一个节点下有 5 个以上的子任务，且每个子任务都需要独立的状态追踪和详细说明时，为子节点创建独立文档
- 子节点文档命名：`{父节点代码}.{子编号}-{关键词}.md`（如 `C9.5-watering-template.md`）
- 父节点文档中通过链接引用子节点文档

### 2.3 内容过短的合并

- 如果一个文档少于 30 行且有紧密关联的同类文档，可合并为一个文档
- 合并后用 `##` 二级标题分隔原内容
- 文件名格式：`{BranchCode}{Node}_and_{Node}-{combined-keyword}.md`（如 `P2_and_P3-player-control-and-interaction.md`）

## 3. 文档内容与格式规范

### 3.1 文档头部

每篇文档必须以元数据区开始：

```markdown
# {文档标题}

> 所属分支：{分支名称}
> 节点编号：{T1/C5/S3 等}
> 状态：`[ACTIVE]` / `[NEXT]` / `[LATER]` / `[RESEARCH]` / `[DONE]`
> 依赖：{相关节点编号}
> 最后更新：YYYY-MM-DD | 基线程：v{版本号}
```

### 3.2 状态标签

| 标签 | 含义 |
|------|------|
| `[DONE]` | 已有可运行实现和基础验收 |
| `[ACTIVE]` | 已有基础实现，当前阶段持续迭代 |
| `[NEXT]` | 建议进入最近一到两个版本 |
| `[LATER]` | 依赖其他分支，适合后续版本 |
| `[RESEARCH]` | 需要实验验证，不能直接承诺产品化 |

### 3.3 节点编号规则

```
{分支代码}{层级编号}
```

- 主节点：`T1`、`C4`、`S3`
- 子节点：`T1.1`、`C4.2`、`S3.1`
- 孙节点（如需要）：`C9.5a`、`C9.5b`

编号在 Issue、提交说明和版本计划中应保持一致。

## 4. 文档间引用规范

### 4.1 相对路径引用

所有引用使用相对于 `docs/roadmap/` 的路径：

```markdown
# 引用同一分支内的文档
详见 [C4 角色与场景交互](./C-characters/C4-character-scene-interaction.md)

# 引用其他分支的文档
详见 [T2 语义世界与空间协议](./T-runtime/T2-semantic-world.md)

# 引用跨分支文档
详见 [分支依赖关系](./99-dependencies.md)
```

### 4.2 引用格式

- **章节引用**：`[C5.2 关系图](./C-characters/C5-memory-personality-schedule.md#c52-关系图)`
- **外部文档引用**：`设计文档：[AI养成陪伴游戏_设计方案](../../../设计方案/AI养成陪伴游戏_设计方案.md)`
- **Issue 引用**：`Issue #123` 或 `PR #456`
- **Commit 引用**：提交 `abc1234`

### 4.3 引用原则

- 使用 Markdown 相对链接，不要使用绝对路径
- 被引用文档移动后，必须同步更新所有引用它的链接
- 优先引用子节点文档而非父节点文档，提供更精确的跳转目标
- 重要节点在 `README.md` 根文档中应有全局可跳转的索引

## 5. 版本与更新规范

### 5.1 更新时间

- 每次编辑文档后，更新文档头部的 `最后更新：YYYY-MM-DD` 字段
- 如果随新版本基线推进，更新 `基线程：v{版本号}` 字段
- 重大结构调整后，更新 `CHANGELOG.md`（可选，位于 `docs/roadmap/CHANGELOG.md`）

### 5.2 版本基线对应

| 基线程 | 含义 | 主要更新的分支 |
|--------|------|----------------|
| `v0.6` | 稳定客厅生活 | T, S1-S3, C4, C5, X1 |
| `v0.7` | 具身生活感 | C9, C2-C4, C7 |
| `v0.8` | 从客厅到住宅 | S2, P2-P3, T2 |
| `v0.9` | 社交与剧本 | C5, D1-D2, C1 |
| `v1.0` | 开源小镇 Alpha | S2, C6, O, X2-X5 |
| `v1.1+` | 参数化与创作者生态 | S4, D3-D4, O5, R |

### 5.3 添加新节点

当新增一个规划节点时：

1. 确认该节点所属分支
2. 确定节点编号（延续该分支现有编号或插入合适位置）
3. 在对应分支目录创建新的 `.md` 文件
4. 更新分支 `README.md` 的子文档索引
5. 更新根 `README.md` 的总规划树（如有需要）
6. 在 `99-dependencies.md` 中添加新的依赖关系（如有）

### 5.4 废弃节点

- 不删除文档，在文档头部状态标注 `[DEPRECATED]` 并说明原因
- 从分支 README 索引中移除或标记废弃
- 依赖该节点的其他文档添加备注


## 7. 与项目 CLAUDE.md 的协作

- 项目根目录 `CLAUDE.md` 包含当前开发**状态**的快照
- 项目根目录 `CLAUDE.md` 同时是代码长度、命名、模块边界和需求追溯的强制规范
- `docs/roadmap/` 包含详细的**规划**内容
- 当规划节点完成后，应同步更新：
  1. 本目录下对应文档的状态标签
  2. 项目根 `CLAUDE.md` 中的模块状态表
  3. 分支 `README.md` 的完成度摘要

代码中的路线图标记必须引用本目录中真实存在的节点。新增或修改函数使用
`[C9.3][T1.2]` 形式标注；研究驱动算法另引用 `docs/KB-02-papers.md` 的论文标记。
详细规则见项目根 [`CLAUDE.md`](../../CLAUDE.md) 的“Claude / Codex 强制工程规范”。
