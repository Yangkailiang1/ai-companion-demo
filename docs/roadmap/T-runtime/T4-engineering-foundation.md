# T4. 工程底座

> 所属分支：T. Runtime 主干
> 节点编号：T4
> 状态：`[ACTIVE]`
> 依赖：T1、T2、T3
> 最后更新：2026-07-27 | 基线程：v0.7

## 职责

确保 Runtime 的可维护性、可靠性和可测量性。

## 规划节点

### T4.1 `[NEXT]` 存档 Schema 与迁移

- 建立存档 Schema 版本号
- 资源版本跟踪
- 向前兼容的迁移脚本
- 不兼容版本检测与用户提示

### T4.2 `[NEXT]` Headless 合同测试

- 给每个关键协议增加 headless 合同测试
- 视觉任务增加截图基准对比
- 新模型导入的自动化检查（朝向、比例、T Pose、骨骼、动画、材质）

### T4.3 `[NEXT]` 性能预算

建立核心性能预算：

| 指标 | 预算 |
|------|------|
| 帧率 | 30/60 FPS |
| 内存占用 | 待定 |
| 模型面数 | 按 LOD 等级约束 |
| 贴图总大小 | 按平台约束 |
| AI 延迟 | P95 < 350 ms |

### T4.4 `[LATER]` 性能监控仪表板

运行时性能指标采集、可视化和异常告警。

### T4.5 `[ACTIVE]` 代码治理与需求追溯

- 项目根 `CLAUDE.md` 已建立文件/函数长度预算、命名、类型和模块依赖规范。
- 所有新增或修改函数必须显式标注路线图节点，例如 `[C9.3][T1.2]`。
- 研究驱动算法必须同时引用 `docs/KB-02-papers.md` 中的稳定论文标记。
- 当前超长编排器采用渐进式“先提取再新增”，不进行一次性重写。
- CognitiveCycle 首轮拆分已完成：767 行降至 482 行，Prompt、动作/表情解析和
  本地回退策略已形成独立模块，并由 `t4_5_cognitive_split_test.gd` 覆盖兼容合同。
- 自主生活与存档验收不再读取玩家真实存档作为前置状态，保证本机和 CI 可重复。
- 后续增加静态检查脚本，自动发现超长文件、超长函数和缺少需求标记的函数。

验收标准：

- 任意函数可以从注释追溯到规划文档；
- 任意 `[DONE]` 节点可以追溯到实现文件和验收脚本；
- CI 阻止新增长度硬超限或无需求标记的项目代码。
