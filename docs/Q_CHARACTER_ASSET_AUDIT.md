# Q 版角色资产审计与接入规范

> 对应需求：C6（角色导入）、C8（角色美术）、O4（开源治理）
> 审计日期：2026-07-27

## 结论

当前 `model/Q版/` 中除小企鹅外的角色包都是 MMD `.pmx` 模型，Godot 不能直接
作为标准角色资产导入；需要先在 Blender 中转换成 `.glb`，再做骨骼、材质、
表情和动作适配。

更重要的是，抽查到的角色包说明包含禁止再分发、禁止商业使用及权利归原游戏
权利方等限制。因此这些文件只能作为本机原型验证素材，不能随本项目的开源
仓库发布，也不能由转换格式来绕过原许可证。正式开源版本需要换成作者自有或
具有明确 CC0、CC BY、MIT 等允许再分发条款的角色资产。

项目侧已经完成 version-1 运行时角色 manifest 和动态适配器注册：转换后的
GLB 可以分别声明动作 clip、语义骨骼和表情 morph 映射，并自动进入 ECNU
剧情规划的 cast 白名单。当前缺口已经从“Runtime 不支持多模型”缩小为
“PMX 资产需要转换、逐角色检查和确认授权”。

## 当前盘点

| 资产 | 源格式 | 当前处理 |
|---|---|---|
| 今汐Q、卡提希娅Q、吟霖Q、折枝Q | PMX + 贴图 | 仅本机候选，不提交仓库 |
| 椿Q、相里要Q、釉瑚Q、长离Q | PMX + 贴图 | 仅本机候选，不提交仓库 |
| 终末地小企鹅 | VRM + Blend | 已有本机 GLB 转换样板；发布前仍须确认授权 |

釉瑚存在两个内容相同命名不同的压缩包，资产整理时应只保留一个本机副本。

## 标准角色包要求

正式可接入角色优先提供：

- `.glb` 或 `.gltf`；VRM 可通过离线工具转换；
- 人形骨骼的 T/A Pose 基准、正面方向和真实身高；
- 材质贴图、BlendShape/表情名称、可用动画清单；
- 明确许可证文件、作者与来源链接；
- 若允许二次分发，明确模型、贴图、动画是否采用同一许可证。

角色包进入项目后必须拥有稳定 `agent_id`，并在
`data/character_runtime_adapters.json` 分别声明动作、骨骼和表情通道映射。
剧情导演和认知系统只输出语义提示，不依赖某个模型的骨骼名称。

## 本机 PMX 验证流水线

1. 在隔离的本机素材目录解压，不复制进 `assets/`。
2. 使用 Blender 的 MMD 导入工具加载 PMX，检查贴图路径与透明材质。
3. 应用比例和朝向，保留原始骨骼与 morph，导出单一 GLB。
4. 在 Godot 中检查蒙皮、法线、透明排序、静止姿态与根节点朝向。
5. 编写该角色的骨骼/动作/表情适配配置并跑角色接入验收。
6. 若授权不允许发布，只在 `.gitignore` 覆盖的本地开发目录引用。

适配配置以 `data/examples/chibi_character_manifest.example.json` 为模板。
运行时由 `character_runtime_binding.gd` 注册，不需要为每个 Q 版角色复制
StoryDirector、LLM、MemorySystem 或动作/表情路由器。

可使用仍在维护的 Blender MMD 工具项目：
[MMD-Blender/blender_mmd_tools](https://github.com/MMD-Blender/blender_mmd_tools)。
其 v4.x 官方兼容表覆盖 Blender 4.2–5.1；本机 Blender 5.0.1 应使用最新
v4.x，而不是旧 `powroupi` 分支。实际批量转换前仍需先用一个角色验证材质、
骨骼、morph 和 GLB 导出结果。

## 需要用户补充的正式素材

为了把“多 Q 版角色小剧场”真正做进可开源版本，请优先寻找至少 2–4 个：

- 可再分发的 Q 版 GLB/VRM 人形模型；
- 带标准 humanoid 骨骼；
- 至少包含眨眼、微笑、难过三种表情；
- 允许项目演示、修改和随仓库发布；
- 最好附带 idle、walk、wave、nod、sit 五个基础动画。

没有附加动画也可以接入，但需要走现有离线动作库的重定向流程。
