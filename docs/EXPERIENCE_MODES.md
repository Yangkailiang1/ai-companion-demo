# 自由模式与演出模式

> 对应需求：C9（自主生活）、D2（导演系统）、D3（AI 辅助剧情）
> 当前版本：v0.8 双模式 MVP

## 模式边界

### 自由模式

自由模式是默认状态：

- `AutonomousBehaviorSystem` 持续评估角色需求、环境状态、日程和关系；
- 玩家普通输入进入目标角色自己的认知循环；
- `@诀 ...`、`诀，...` 等目标写法仍然有效；
- 角色记忆、人格、长期计划和玩家关系彼此隔离；
- 角色可以自发浇水、休息、观察、交谈，玩家输入拥有打断优先级。

### 演出模式

演出模式把输入框从“和角色聊天”切换为“提交自然语言剧本”：

1. 玩家输入故事要求；
2. `StoryPlannerService` 把场景和角色能力提供给 LLM；
3. LLM 规划 cast、Beat、走位、注视、动作、表情、对白和物体交互；
4. `StorySchemaValidator` 执行严格白名单校验；
5. 无效结果最多反馈给 LLM 自动修复一次；
6. 合法 Story JSON 交给 `StoryDirector` 确定性执行。

LLM 不能直接访问 Godot 节点，也不能生成任意代码。运行时只执行已注册角色、
安全路点、已知动作/表情和物体声明的 affordance。

## 玩家命令

| 输入 | 结果 |
|---|---|
| `!演出` | 进入演出模式，后续普通输入都视为剧本 |
| `!演出 <剧本>` | 进入演出模式并立即提交剧本 |
| `!performance <剧本>` | 英文等价命令 |
| `!自由` / `!free` | 取消未完成规划/演出并恢复自主生活 |
| `!模式` / `!mode` | 显示当前模式 |
| `!剧情 cozy_evening` | 直接重放已保存 Story JSON，主要用于回归和创作预览 |

示例：

```text
!演出 咕咕嘎嘎发现诀有点累，于是邀请她一起坐到沙发前看电视，
咕咕嘎嘎负责开电视，诀答应后两人聊了几句奶茶。
```

## LLM 获得的规划上下文

Planner 每次动态构造上下文，不把具体剧本写死在代码中：

- 已注册 `agent_id`、显示名和角色人设；
- 每个角色与本次剧本最相关的少量独立记忆；
- 每个模型当前真正支持的动作映射；
- 当前语义物体、状态和 affordance；
- `RoomNavigation` 中可验证的安全路点；
- Story JSON 契约、Beat 上限和双角色避免重叠规则。

玩家文本被明确标记为“剧情要求”而不是系统指令。即使 LLM 受到提示注入影响，
最终仍必须通过本地白名单验证。

## 配置与失败行为

动态编排复用 `data/llm_config.json` 中 CognitiveCycle 已加载的模型配置，不复制
API Key。未配置模型时，演出模式会明确报告错误，不会用写死的剧情冒充 LLM
规划，也不会把剧本误发给某个角色进行聊天。

ECNU 实测使用 60 秒单次请求窗口；`HTTP 0` 或 5xx 最多独立重试一次。网络重试
和 Schema 内容修复分别计数，均不会无限请求。真实验证结果见
[ECNU 动态剧情编排真实验证](./ECNU_STORY_PLANNER_VALIDATION.md)。

演出模式在 Planner 失败后仍保持激活，玩家可以修改剧本重试或输入 `!自由`。
导演完成后同样保持演出模式，方便连续提交多个场次；角色自主调度只有返回自由
模式后才会恢复。

```bash
  --headless --log-file /private/tmp/experience_modes_check.log \
  --path . --script scripts/debug/experience_modes_check.gd
```

验收不依赖网络：它注入一份等价 LLM JSON，验证模式边界、提示上下文、非法输出
拒绝、合法规划执行、双角色对白、物体交互，以及回到自由模式后的对话路由。
